## 1. 用户旅程

证据表：

| 阶段 | 用户目标 | 用户动作 | 页面反馈 | 用户决定 | 页面/资产状态变化 | 问题或阻力 | 证据 |
|---|---|---|---|---|---|---|---|

三泳道图只保留：用户、产品界面、系统结果。加入有证据的正常、修改、失败、中断和恢复路径；判断节点写明条件并附证据编号。

输出顺序：查看范围 → 无法确认项 → 证据表 → 三泳道图 → 情绪/痛点 → 机会点 → 最值得讨论的问题。

## 2. Agent 契约

每个 Agent 使用以下结构：

1. 核心目标与触发条件。
2. 输入表：输入项、来源类型、必填/可选/未知、用途、等级、证据。
3. 可观察判断：问题、输入完整性、确认门、停止/回退、工具成功、质量验证。
4. 工具表：功能名、调用者、前置条件、参数、执行证据、成功/失败、幂等、状态写入。
5. 输出表：输出项、自然语言/组件/字段/资产/状态/下游任务、消费者、等级、证据。
6. 上下文表：对象、读/写、生产者、消费者、更新时机、版本、失效依赖、等级、证据。
7. 完成条件、异常重试、下游交接、未知问题。

产品级附表：Agent 清单、工具总表、全局上下文字段表、生产者—消费者表、输入—判断—工具—输出—交接图、事实/推断/未知清单。

## 3. 功能等价 Prompt

先回答边界十问：解决什么、何时接管、谁触发、交给谁、属于/不属于什么、修改是否重触发、何时停止、何时自动继续、何时等待确认。

Prompt 固定结构：

1. Agent 名称、角色、目标与边界。
2. 输入契约与全局上下文协议。
3. 工作流程与工具调用规范。
4. 用户确认、结果验证、修改与回退。
5. 异常处理与状态机。
6. 下游交接、完成条件、输出格式。

推荐最小状态集：`waiting_input`、`planning`、`waiting_confirm`、`executing`、`validating`、`retrying`、`completed`、`failed`、`interrupted`、`handoff`。根据证据删减，不为完整性虚构状态。

规则—证据表：规则、类型、证据编号、证据摘要、推导理由、未知项。测试集覆盖：正常、缺输入、局部修改、工具失败、中断、状态冲突、重复请求、下游失败。

## 4. 全景架构

端到端流转表：

| 步骤 | 触发者 | 处理者 | 读取 | 判断 | 工具 | 结果/资产 | 状态写回 | 用户确认 | 下游 | 失败分支 | 证据 |
|---|---|---|---|---|---|---|---|---|---|---|---|

按实际证据检查九层：

1. 用户与渠道；
2. 交互与工作台；
3. 产品应用；
4. Agent 与编排；
5. 工具与服务；
6. 模型接入与路由；
7. 全局上下文与数据；
8. 知识与公共资产；
9. 基础设施与治理。

上下文表至少包含：语义、生产者、消费者、读写时机、版本、失效依赖、页面证据和等级。区分项目数据、用户私有资产、平台公共资产、可复用知识和反馈数据。

架构输出顺序：执行摘要 → 证据与缺口 → 功能域 → 五条流 → 九层架构 → Agent/工具/上下文关系 → 模型与知识 → 实体/ER → 时序 → 主图 → As-Is → To-Be → 风险 → 追溯表 → 未知问题。

As-Is/To-Be 表：

| 维度 | As-Is 当前证据 | 问题 | To-Be 建议 | 验收指标 |
|---|---|---|---|---|

优先检查：统一状态事实源、结果质量门、资产依赖与局部重算、幂等重试与扣费、真正完成门、可观测性、权限与隐私。

## 5. 总体验收

- 完整性：阶段交付独立、范围与缺口明确、关键结论可追溯。
- 真实性：不冒充隐藏事实；计划与执行、回复与状态、资产与完成分开。
- 可复用性：契约可作为 Prompt/架构输入；As-Is 与 To-Be 可独立阅读。
- 可读性：字段一致、图例清楚、箭头有语义、复杂图可滚动或分层阅读。
- 安全性：无凭证泄露、无未授权写操作、动态证据有时间戳。
